Vision vs Live. Live privacy is SHA3-512 commitment + nullifier opening: the node sees the trapdoor. claim=opening_not_zk. Not Groth16, Bulletproofs, or ZK-Shield. privacy_mint_zk is an ML-DSA wrap, not a circuit — this page does not call it. ZK path is scaffold / fail-closed (zk_pending → future zk_v1 only after verify works). Design: privacy-real (repo docs/PRIVACY_REAL_V1.md). Fast path is separate (ADDITION_FAST_V1 · docs/FAST_PATH_V1.md) — not this page’s product surface. Mint/spend need ADDITION_PRIVACY_MASTER_KEY (≥32 chars) on the daemon. Without it the node returns error: ADDITION_PRIVACY_MASTER_KEY not set or too short (min 32).

What ships today

Opening RPCs on loopback: privacy_note_prepare, privacy_mint_open, privacy_spend_open. Live getinfo / privacy_status keep privacy_claim=opening_not_zk.

What is scaffold

privacy_mint_zk_v1 / privacy_spend_zk_v1 reject every proof (claim=zk_pending). See privacy-real / docs/PRIVACY_REAL_V1.md.

What is research goal

Real zk_v1 only when a verifier accepts proofs on-node. No fake ZK marketing. PQ stays ML-DSA-87 / SHA3-512 pq_mode=strict.
