Chosen approach (ADDITION, C++20)

A separate network id so the fast path cannot be confused with mainnet PoW:

  1. Network profile — network_id=ADDITION_FAST_V1, network_mode=fast, distinct genesis / data dir / ports.
  2. Consensus sketch — leader schedules, pipelined block propagation, parallel execution. Mainnet keeps memory-hard PoW.
  3. Crypto unchanged — ML-DSA-87 / SHA3-512, pq_mode=strict.
  4. This fill PR — typed pipeline stages + fail-closed message validation (SHA3-512 digests). Boot remains refused. No invented TPS.

Fail-closed rejects wrong network_id, bad digest, out-of-order kind, empty body, and bodies containing CLAIM_FAST_LIVE / CLAIM_MEASURED_TPS / Solana-TPS slogans.

Fail-closed rules

  • --network fast / --fast refuses to boot while fast_path_pipeline_shipped()==false.
  • Loading fast genesis/config onto mainnet or testnet modes is rejected.
  • Mainnet --mainnet path is unchanged: ADDITION_MAINNET_V1, memory_hard, target 0x000000FFFFFFFFFF.
  • getinfo / protocol_status never prints a measured Solana TPS figure. throughput_claim=none.
  • Typed stage progress must not flip kFastPathPipelineShipped.
