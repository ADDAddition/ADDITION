Specs & comparison

ADDITION's column describes the code as it stands (pre-mainnet). The other columns give the usual public description of each chain. Neither price nor TPS is compared.

ADDITION parameters

SignaturesML-DSA-87 (NIST FIPS 204) only, via liboqs. No ECDSA, no Falcon. pq_mode=strict.
HashingSHA3-512
Supply50,000,000 ADD hard cap, genesis mints 0, no tail emission
Block time20 s target, LWMA retarget (180-block window)
Block reward4 ADD (heights 1 to 5,681,818), 2 ADD (to 11,363,637), then 1 ADD until the cap at height 27,272,727 (about 17.3 years). After that, fees only.
Proof of workMemory-hard PoW over SHA3-512
StakingTicket staking activates at height 14,772,727 (when 37.5M ADD have been emitted, about 9.4 years). From then on 30% of each reward goes to voting stakers. Equivocation is slashed.
Private paymentsShielded pool with STARK proofs, nullifiers and encrypted memos
Layer 2Payment channels with HTLC multi-hop routing and timelocks
MessagingAMLS1 end-to-end messaging: ML-DSA-87 identities, ML-KEM-1024 handshake; the node only relays
NetworkP2P over Tor v3 onion services with a post-quantum handshake. Mainnet seeds are onion-only, no DNS seeds.

Values come from include/addition/config.hpp in the source code. Throughput is not advertised.
